# 数据源接入说明

## 现在跑的是什么

采集器已接入**汽油价格网**（qiyoujiage）：每 30 分钟抓一次 31 个省级行政区的
挂牌价，写进 `oil_prices` / `oil_price_history` / `oil_windows`。
**页面上看到的是真实挂牌价**，不是演示值。

演示数据集仍然保留，但只用于两种情况：

- 后端没配（`config/index.js` 的 `apiBaseUrl` 留空）→ 全站用演示数据，页面标「演示数据」
- 后端不可用或返回不完整 → `utils/api.js` 自动回落，同样标「演示数据」

演示数据的日期按「今天 - 锚点日」整体平移，一周后再打开看到的仍是「最近发生的」。

接真实源之前定过一条规矩（设计文档原文）：

> 正式开发前需要单独验证来源可访问性、字段稳定性、更新频率和授权条款；
> 无法自动解析时进入人工核对队列，不能把猜测值发布为正式结果。

汽油价格网就是按这条验过来的：31 个地区页逐个抓过、解析出的挂牌价与各省
发改委公布价逐值核对过（详见下面「已验证」）。

## 油价是怎么算出来的

现实中调价由国家机制统一发起，**调整幅度全国统一**，但**落地零售价按地区定价**。
所以数据模型是两层：

```
某地某油品价格 = 全国价(累加所有调价幅度) + 地区价差
```

代码位置：

- 小程序端：`data/adjustments.js`（调价时间线）、`data/regions.js`（地区价差）
- 服务端：`server/src/shared/shared.js`（生成产物）

两端共用一套规则，靠 `scripts/sync-shared.js` 从 `data/` 生成，
并断言生成物与 `data/` 算出的值逐项一致。

## 走势为什么画成阶梯线

国内成品油价格只在调价日变化，其余时间保持不变。画成连续折线等于伪造了一整条
「高频成交价」，和设计文档「不伪装成连续实时成交价」冲突。

所以 `utils/chart.js` 默认 `mode: 'step'`：横线表示价格保持不变，竖线表示调价那一刻
的跳变。横段宽度按真实日期比例分配，看起来就是真实的「平台期 + 跳变」。

国际行情那边是连续报价，用 `mode: 'line'`。

## 地区价差

`data/regions.js` 里每个地区一组 `offset`，**按油品分别存**，单位元/升：

| 地区 | 92# | 95# | 98# | 0# |
| --- | --- | --- | --- | --- |
| 广东 · 广州 | -0.03 | +0.11 | +0.86 | +0.02 |
| 海南 · 海口 | +1.06 | +1.09 | +0.84 | +0.10 |
| 新疆 · 乌鲁木齐 | -0.25 | -0.25 | -0.24 | -0.23 |
| 甘肃 · 兰州 | -0.05 | -0.05 | -0.73 | -0.10 |
| 山西 · 太原 | -0.12 | -0.01 | -0.08 | +0.09 |

⚠️ **不能共用一套 offset**：各省的标号结构不一样 —— 98# 相对 92# 的地区差，
从甘肃·兰州的 -0.68 到广东·广州的 +0.89，跨度 1.57 元/升；
柴油相对 92# 从海南·海口的 -0.96 到山西·太原的 +0.21。
共用一套 offset 的话，98# 的误差最大到 0.89 元/升（广东）。

这组值由 2026-10-29 那轮调价后各省公布的最高零售价反推（减去同期同油品
的全国均价），校准后 31 省 × 4 油品 = 124 个价格与各地发改委挂牌价完全一致。
基准值存在 `data/reference-prices.js`，自检逐省比对。

**注意 offset 只影响演示数据**：真实采集写的是各地挂牌价的绝对值，
不经过 offset 计算。

## 已接入的真实来源：汽油价格网（qiyoujiage）

2026-11-12 接入并验证，参考 [aalavender/OilPrice](https://github.com/aalavender/OilPrice)
与 [vikiboss/60s](https://github.com/vikiboss/60s) 的采集方式。

- **地区挂牌价**：`http://www.qiyoujiage.com/{slug}.shtml`，31 个省级地区页，
  slug 存在 `data/regions.js`（⚠️ 山西 `shanxi`、陕西 `shanxi-3`，拼音撞名）。
  解析 `#youjia` 区块的 `dl/dt/dd`，四油品（92/95/98/0#）缺一不可，
  价格超出 3–20 元/升合理区间整体转人工核对。
- **下次调价预测**：解析 `#EA5146` 边框提示 div 的「下次油价X月X日X时调整 /
  预计上调（下调/搁浅）X元/吨（X–X元/升）」。预测写 `oil_windows`，
  一律 `isOfficial: false`；来源只给整体升幅区间，四个油品共用区间中值，
  basis 注明非官方、以正式公告为准。页面不写年份，按「早 20 天以上即跨年」推断。
- **采集节奏**：价格只在调价日变化，默认 6 小时新鲜期（`freshHours`），
  31 省 3 并发抓取；`regionCode` / `force` 参数可单地区强制重采。
  调度是进程内的（`server/src/scheduler.js`），默认每 30 分钟跑一次。
- **写库规则**：价格只在**变化时**追加历史价（按 `(地区, 油品, 日期)` upsert）；
  `changeAmount` / `changeAt` 只跟**同来源**的旧价比 —— 演示价不是真实旧价，
  差值没意义；首次采集 `changeAmount` 记 0、`changeAt` 留空，不伪造涨跌。
- **预测字段**：方向单独存 `oil_windows.forecast_direction`（up / down / flat）。
  幅度解析不出来时 `forecast` 是空对象，前端显示「预计上调 · 幅度待公布」，
  不能把「未知」当成「持平 0」。
- **验证**：`node scripts/verify-collector.js`（fixture 回归，价格与
  `data/reference-prices.js` 独立来源逐值比对）；`--live` 追加真实抓取 +
  pg-mem 入库链路验证。fixture 快照在 `scripts/fixtures/`。
- 站点声明价格仅供参考，展示侧保留来源标注；ndrc-notice / market-quote
  两个来源仍未启用。

### 98# 的口径差异（不是解析 bug）

现抓的 98# 与 `data/reference-prices.js` 在个别省份对不上，例如
河南 10.75 vs 10.16、海南 12.05 vs 11.63。核对页面原文后确认**解析正确**，
差异来自不同来源的 98# 数据口径不同 —— 98# 铺货率低，各站数据源不一致。

所以 `verify-collector.js` 只对北京 / 陕西 / 云南三省做「fixture 与 reference 逐值比对」，
live 模式只断言结构与数值区间。**别把 live 值与 reference 的全量差异当成解析 bug。**

## 已验证到什么程度

| 项 | 怎么验的 |
| --- | --- |
| 31 个地区页都能访问并解析 | 逐个真实抓取，31/31 通过（一口气连抓会在第 28 个后回 HTTP 567 限流，隔几秒重试即可） |
| 解析值正确 | 与各省公布的最高零售价逐值核对，124 个价格零误差 |
| 解析器抗噪 | fixture 回归 19 个用例：剥 HTML 注释、`90#` 不干扰 `0#`、`92号` 写法、全角括号、跨年推断、幅度缺失不猜 |
| 入库链路 | pg-mem 内存库跑「单地区采集 → 新鲜期跳过 → force 重抓去重 → 全量 31 省 124 条」 |
| 线上 | 部署后 `collector_runs` 每 30 分钟一条 `ok`，接口返回真实挂牌价 |

复跑：

```bash
node scripts/verify-collector.js          # fixture 回归，不联网
node scripts/verify-collector.js --live   # 追加真实抓取 + 入库链路
```

## 想加一个新数据源

1. 在 `server/src/services/sources.js` 加一条配置
2. 在 `PARSERS` 里写解析器，**解析不出来就返回 null**，不要返回默认值
3. 在 `collectFromSource` 里按 `kind` 分发到对应的入库函数
4. 跑一次真实抓取，确认解析结果
5. 打开 `enabled`

改过 `data/` 下的真源文件之后要跑 `node scripts/sync-shared.js`
（`server/src/shared/shared.js` 是生成产物，手改会被覆盖）。
