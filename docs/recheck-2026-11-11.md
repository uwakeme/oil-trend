## 五、待处理问题详解

### R1 同步状态语义断裂（对应上轮 P0-4，本轮最优先）

**现象分两头，都不如实：**

1. **演示侧没改**：`data/notices.js:95-98` 的 `SYNC_STATUS` 仍是
   `status: 'ok'`、`lastCheckedAt: '2026-11-10T18:20:00+08:00'`、`sourceName: '服务端定时采集（演示）'`。
   时间平移后是「当天 18:20」，而复查时间是 13:47 —— 显示的是**未来时间**。
   `pages/notice/notice.js:112` 把 `ok` 映射成「自动同步正常」，于是两个真实来源全关、根本没有任何采集的演示数据，界面仍宣称自动同步正常。`verify-data.js` 的输出也印证：`条数: 5  同步: ok @ 2026-11-11T18:20:00+08:00`。
2. **云端新增的 `idle` 前端不认识**：`oilCollector/index.js:308` 在 `allSkipped` 时写 `status:'idle'`，`oilApi/index.js:347` 在没有采集记录时也兜底 `idle`；但 `notice.js:112-113` 只有 `ok` / `pending` / 其他分支，`idle` 落到 `其他` → 文案「**同步异常**」+ `className:'error'` 红字。部署后（两个来源仍全关）必然是 `idle`，用户看到的比修复前更糟：不是「正常」也不是「未接入」，而是「异常」。

**影响**：直接违反「必须如实展示当前来源／不假装实时」的硬约束；R1 的第 2 点是本轮修复**新引入**的。

**建议**：
- 演示侧 `SYNC_STATUS.status` 改为 `idle`，`lastCheckedAt` 改为相对当前时刻生成（或干脆不展示具体时刻，只写「演示数据，未启用真实采集」）。
- `notice.js` 增加 `idle → '真实数据源尚未接入'`，样式用中性/提示态而非 `error`；`partial`、`error` 也各给明确文案，别再用「其他」兜底。
- 加一条断言：`sync.status` 的每一种取值都要有对应文案，避免以后再加状态时再次漏映射。

### R2 未复核公告仍可发布到首页（对应上轮 P2-2）

**位置**：`oilApi/index.js:82-89` 的 `getLatestNotice()` 只按 `kind:'official'` 排序取一条，**没有** `reviewStatus === 'approved'` 条件；而同文件 `:95` 的 `getNotices()` 已经加了过滤。`actionHome:234` 用前者生成首页「最新调价通知」卡片。

### R7 时区一致性隐患（本轮潜在，需云端实测）

生成的 `cloudfunctions/_shared/shared.js:364-371`：

```js
function localDayNumber(date) {
  return Date.UTC(date.getFullYear(), date.getMonth(), date.getDate());
}
function offsetDays() {
  return Math.round((localDayNumber(new Date()) - anchor) / 86400000);
}
```

小程序端 `utils/demo-clock.js` 同样按**本地日历日**算偏移。两端都正确，但两者所在时区可能不同：若云函数服务器是 UTC 而用户是 UTC+8，北京时间 00:00–08:00 之间两端 `offsetDays()` 差 1，调价日期、窗口倒计时可能差一天。当前 `currentPrice()` 是累加全部幅度、不受影响，但 `changeAt` / 窗口会分叉。

**建议**：两端统一按 UTC+8（`new Date(Date.now() + 8 * 3600000)` 取 UTC 日历日）计算，或由云函数把日期参数化、不在服务端自行推断「今天」。部署后实测一次两端 `today()` 是否一致。

### R8 云函数无加载期门禁（登记）

`scripts/check-modules.js:21-23` 的 `RUNTIME_DIRS` 只有 `pages / components / utils / data / config` + `app.js`，注释写「云函数不在小程序包里，另行 `node --check`」。但本轮文档 10.4 记录的五页白屏事故恰恰是「删了函数体、留着导出项」的加载期 `ReferenceError`，`node --check` 只做语法解析，**挡不住这类错误**。云函数侧没有等价门禁。

**建议（登记，不阻塞）**：后续给云函数加一份 stub `wx-server-sdk` 的加载冒烟检查，或至少在部署前跑一次 `require` 冒烟。
