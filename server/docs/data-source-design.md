# 数据源重构：多源协作 + 近一年历史油价

> 状态：设计已确认（2026-11-16），待实施
> 影响面：`server/src/services/sources.js`、`server/src/services/collector.js`、`data/regions.js`
> 不改：数据库表结构、小程序端代码、`utils/api.js`

## 1. 要解决的问题

首页与走势页的历史价只有 **5 个点**（全在 2026-11-12 ~ 11-16），因为采集器
2026-11-12 才上线、且只写「当天生效价」。结果是：

- 走势图的 3m / 6m / 1y 三个周期返回的是同一组 5 个点（只有坐标轴不同），
  一年图只有最右侧一小段台阶；
- 走势页的「调价节点数」恒为 0（`oil_adjust_events` 生产库一直是空的）；
- 「四油品每升幅度测算」只能拿到本轮前后的快照，历史轮的幅度全空。

用户诉求：**补足近一年数据，让走势图画得出来。**

### 2.1 xmgcn 省份页结构

省份索引页 `https://www.xmgcn.com/{slug}/` 一个页面同时给出现价与历史：

```
<div class="price-card n92">
  <div class="oil-name">92号汽油</div>
  <div class="price-main">
    <span class="price-value">8.39</span>
    <span class="price-unit">元/升</span>
    <span class="price-change down"> -0.52 </span>
  </div>
</div>
...
<div class="history-table">
  <table>
    <thead><tr><th>日期</th><th>89号汽油</th><th>92号汽油</th><th>95号汽油</th><th>98号汽油</th><th>0号柴油</th></tr></thead>
    <tbody>
      <tr><td>2026-11-13</td>
          <td class="price-cell"><div>7.79</div><div class="change-cell change-down">-0.48</div></td>
          ...</tr>
    </tbody>
  </table>
</div>
```

要点：

- 油品 class 是 `n89 / n92 / n95 / n98 / n0`，**结构化、无歧义**；
- 历史表每行是「日期 + 各油品（价格 + 涨跌）」；
- 31 省页面结构完全一致；
- 89# 汽油在内蒙古/吉林/新疆/河南/湖北/辽宁/黑龙江是 `-`（这 7 省不供 89#），
  本项目只做 92/95/98/0，不受影响。

### 2.2 覆盖度与可信度（实测）

- **31 / 31 省**全部拿到表，每省 **31 行**，覆盖 **2025-09-10 → 2026-11-13**（30 轮调价）；
- 换算成入库行数：`31 省 × 31 期 × 4 油品 = 3844 条`；
- 广东 92# 历史表最新值 **8.39** = 广东省发改委公布的每升价，涨跌 **−0.52** = 线上测算值；
- **31 省最新价 vs 线上现价：差异 0.00，31/31 全对**；
- 这些是**各省公布的最高零售价本身，不是推算值**。原先设想的「官方吨价反推每升」
  （系数 92#≈0.00080 / 95#≈0.000855 / 98#≈0.00097 / 0#≈0.00081）作废 ——
  有真实数据就不拿推算冒充。

### 2.3 已知脏数据与坑

| 坑 | 表现 | 应对 |
| --- | --- | --- |
| 密集请求返回残页 | 表格 `<tbody>` 为空（首测 7/31 省失败） | 限速 + 行数校验 + 重试 |
| 源站数据本身有脏值 | 湖北 98# 某轮涨跌 −0.36，明显偏离各省中位数 | 跨省一致性闸门（MAD） |
| 源站偶尔漏更 | 某些省某个油品的价格停在旧值 | 序列跳变闸门 + 区间定界 |
| slug 与本项目不同 | 西藏=xicang、内蒙古=namenggu、陕西=shanxi2（其余 27 省同名） | 每源一套 slug 映射 |
| xmgcn 无预测 | 页面没有「下次调价预测」 | 预测仍由 qiyoujiage 独家提供 |

## 3. 职责划分

一个源不再等于一种数据，而是按**职责**声明能提供什么：

| 源 | kind | provides | 抓取量 | 协议 |
| --- | --- | --- | --- | --- |
| `xmgcn` 油价网 | `price` | price + history | 31 省 × 1 次（一次请求同时给现价与 30 期历史） | HTTPS ✓ |
| `qiyoujiage` 汽油价格网 | `forecast` | forecast + price（兜底/校核） | 平时抽 3 省；主源某省失败才按需补该省 | HTTP ✗ |
| `ndrc-notice` 发改委 | `notice` | notice | 不变 | HTTPS ✓ |

- **xmgcn 是现价与历史的唯一真源** —— 两者同源同页，天然自洽；
- **qiyoujiage 只保留三件事**：① 下次调价预测（全网唯一）；② 主源失败时的现价兜底；
  ③ 交叉校核；
- 交叉校核抽查 **广东 / 山东 / 新疆** 3 省（南 / 东 / 西，各省价差各异，异常更容易露出来），
  校核对的是「qiyoujiage 现价 vs 库里 xmgcn 现价」，**偏差 > 0.02 元/升 记告警但不阻断**；
- 请求量：31（xmgcn）+ 3（qiyoujiage 抽查）= 34 次/轮，比现状（31 次）只多 3 次，
  却换来 14 个月历史 —— 性价比最高。

## 4. 采集编排与降级

```
价格源组（按 priority 排序）：xmgcn(1) → qiyoujiage(2)
  逐省：xmgcn 成功 → 采用
        xmgcn 失败 → 该省交给 qiyoujiage 补
        两个都失败 → 该省转人工核对（不显示任何猜测值）
预测：qiyoujiage 抽 3 省 → 取第一个解析成功的 trend → oil_windows
校核：qiyoujiage 抽的 3 省现价 vs 库里的 xmgcn 现价 → 偏差告警
```

节流：3 并发 worker + 每请求间隔 800ms + **历史表行数 < 20 判定为残页 → 重试 1 次**。

## 5. 数据落库

| 表 | 写入方 | 内容 |
| --- | --- | --- |
| `oil_prices` | xmgcn（qiyoujiage 仅兜底时） | 当前价，`source` 标记来源 |
| `oil_price_history` | xmgcn | 30 期历史价，`source='xmgcn'`，按 (region,fuel,date) 幂等 upsert |
| `oil_windows` | qiyoujiage | 下次调价预测（`isOfficial=false`） |
| `oil_adjust_events` | xmgcn | **新增**：从历史价的变化点推导调价节点，`source='xmgcn'` |

`oil_adjust_events` 原来一直是空的（公告只给吨价、不给每升幅度，`saveAdjustEvent`
拿不到 `deltas` 就写不进去）。有了历史实测值，每个调价日都能算出**实测**的每升幅度，
走势页的「N 次调价」不再恒为 0。

⚠️ 口径：这些幅度是**各省挂牌价的实测差值**，不是官方公布值。展示层必须写明
「据各省挂牌价实测」，不能写成官方公布值（与 `utils/format.js` 的 `MEASURED_NOTE` 一致）。

## 6. 历史数据入库闸门（5 道）

源站有脏值，且历史是**一次性回填**（库里没有旧值可比），不能用「与上次采集价落差」
那套逻辑。历史单独设闸门：

| 闸门 | 判据 | 动作 |
| --- | --- | --- |
| G1 区间 | 3 ≤ price ≤ 20 元/升 | 丢点 + 告警 |
| G2 序列跳变 | 同省同油品相邻两期 \|Δ\| > 1.0 元/升 | 丢点 + 告警（正常一轮调价 ≤ 0.6） |
| G3 首尾自洽 | 历史表首行价格 == 同页现价 | 不等 → **整省丢弃**（说明解析错位） |
| G4 跨省一致性 | 同日同油品偏离各省中位数 > max(0.5, 3×MAD) | 丢点 + 告警 |
| G5 时序 | 日期单调递增、无重复 | 丢点 + 告警 |

G4 需要跨省数据，必须**所有省解析完再统一校验**，不能边抓边写。

## 11. 国际行情源（2026-11-28 接入）

国际页原先展示的是 `data/markets.js` 里的**演示常量**（Brent 78.42 / WTI 74.16
+ 伪随机曲线），`market-quote` 源一直 `enabled:false`、URL 也是空的 —— 页面上那个数
从来不是真实行情。现在接入真实源。

### 11.1 源调研结论（2026-11-28 实测）

| 候选 | 可达 | 快照字段 | 历史曲线 | 结论 |
| --- | --- | --- | --- | --- |
| 东方财富 `push2` / `push2his`（`102.CL00Y`） | HTTPS ✓ | 现价/涨跌/开高低/昨收/报价时间 ✓ | 5 分钟线 + 日线 ✓ | **纽约原油用它** |
| 新浪财经 `hq.sinajs.cn`（`hf_OIL`） | HTTPS ✓ | 现价/涨跌/开高低/昨收/报价时间 ✓ | ✗ | **布伦特用它**（只要快照） |
| CNBC `quote.cnbc.com`（`@CL.1` / `@LCO.1`） | HTTPS ✓ | ✓ | ✗ | 布伦特只给结算价（开/高/低都是 0），落选 |
| Yahoo `query1.finance.yahoo.com` | HTTP 403 | — | — | 落选 |
| MarketWatch / Investing | 401 / 403 | — | — | 落选 |
| 汇通网 fx678 | 页面可达 | 实时价走 **WebSocket** | 历史接口返回空 | 落选 |
| 新浪 K 线 / 腾讯 K 线 | 返回 null / 参数错误 | — | — | 落选 |

**东财没有 ICE 布伦特**：它的外盘市场只有 COMEX（m:101）、NYMEX（m:102）、
ICE 农产品（m:108，棉花/糖），布伦特原油在它那儿根本不存在
（`102.OIL00Y`、`102.B00Y` 等一串 secid 全部返回 `data:null`）。所以布伦特只能走新浪。

### 11.2 ⚠️ 口径：布伦特是 CFD，不是 ICE 期货

这是最容易让用户觉得「数对不上」的地方：

| 来源 | 品种 | 2026-11-27 报价 |
| --- | --- | --- |
| 新华社（结算价） | ICE 布伦特 **1 月**合约 | **95.44** 美元/桶（-1.17%） |
| 新浪 `hf_OIL` | 布伦特原油 **CFD**（场外差价合约） | **90.70** 美元/桶（约 -1.06%） |

两者都是真实报价，但**不是同一个东西**（新浪自己的品种页标题就是
「布伦特原油CFD(OIL)」；`hf_CL` 的标题是「纽约原油CFD(2701)」）。
差 4~5 美元/桶是 CFD 与期货的基差，不是谁错了。

界面必须把口径写出来，否则用户拿页面上的 90.70 去比新闻里的 95.44，
只会认为这个页面不准 —— 口径真源在 `data/markets.js` 的 `MARKET_INSTRUMENTS`
（服务端副本由 `scripts/sync-shared.js` 生成），国际页在信息条上显示 `basis`。

### 11.3 采集与落库

- **快照**：`push2.eastmoney.com/api/qt/stock/get?secid=102.CL00Y&**fltt=2**&...`
  —— 不带 `fltt=2` 时字段是放大 100 倍的整数（f43 给 8333 而不是 83.33），
  解析器用价格区间（10~300 美元/桶）挡住这种情况；
- **历史**：`push2his.eastmoney.com/api/qt/stock/kline/get`（`klt=5` 分钟线、
  `klt=101` 日线）。日线点**保持纯日期**（不补 00:00），否则图上会显示
  「11-27 00:00」；
- **布伦特**：新浪快照没有历史曲线，曲线靠**采集时点累积**（每轮一个真实报价点）。
  休市时报价时刻不变 → 点数不涨，这是事实，不是 bug；
- **曲线合并**（`collector.js` 的 `mergeMarketPoints`）：同一时间戳留最后一个；
  同一天既有日线又有分钟线时**留分钟线**（日线那根是重复台阶）；
- **入库是合并不是覆盖**：库里已有的 + 本轮抓到的 + 本次快照，
  某一次 K 线接口挂掉不会把历史抹成空。

### 11.4 时间与编码口径

- 东财的 K 线标签与报价时刻都是**北京时间**（UTC+8），曲线上所有时间统一按
  UTC+8 的墙上时间解释（`seriesTime` 统一减 8 小时），日线点与分钟线点才在
  同一条时间轴上；
- 新浪的响应是 **GB18030**（品种名是中文），抓取层按 `content-type` 解码
  （`http-client.js` 的 `decodeBody`），按 UTF-8 解会变乱码；
- 新浪的行情接口要带来源页 `Referer`，否则回空。

### 11.5 授权条款

东方财富与新浪的公开行情接口都**不是**官方授权的数据接口：本项目把它们当作
市场趋势参考，展示侧保留来源与口径说明，不作交易依据。若要商用，需另行取得
数据授权。

## 12. 演示数据全部删除（2026-11-28）

### 12.1 为什么删

小程序端原来有一套「本地兜底演示源」：后端一挂，就回落 `data/demo.js` 里的内置数据 ——
24 条调价时间线、31 个地区的价差、5 条通知、8.94 元的全国均价、
国际行情的 78.42 / 74.16。

问题不是「数据不准」，是**用户看不出来它不准**：
页面顶部只挂一条黄色提示（演示数据 · 非实时行情），其余部分和真数据一模一样 ——
调价窗口、走势阶梯线、通知详情都能看、能点、能用。
后端挂了十分钟，用户可能十分钟都以为油价就是这样。

### 12.2 删了什么

- `data/demo.js`（本地兜底源）、`data/notices.js`（演示通知与窗口）、
  `data/adjustments.js`（演示调价时间线）、`utils/demo-clock.js`（演示时钟）；
- `config/index.js` 的 `dataSource`（'demo' 模式）与 `demoAnchorDate`；
- 服务端共享模块里的 `ADJUSTMENTS` / `NATIONAL_BASE` / 价格阶梯 / 演示时钟。

### 12.3 现在的行为

| 情况 | 界面 |
| --- | --- |
| 后端正常 | 真实数据，来源条写「真实数据 · 服务端定时采集」 |
| 后端连不上 | 失败态 + 「重新加载」按钮（五个页面都是） |
| 后端说该地区/该品种还没数据 | 空态（顶层 `empty:true`），写清楚为什么没有 |

「合法为空」与「后端没给成」仍然要分开：
后端在合法为空时返回顶层 `empty:true`，前端的 `hasExpected` 见到它就放行（显示空态）；
真失败则 reject，页面显示失败态。

### 12.4 演示数据搬去了哪

演示数据只属于测试：调价时间线与价格阶梯搬进 `server/scripts/test-fixtures.js`，
用来给内存库灌一套自洽的种子，并验证「地区价差」模型与各省公布基准价逐项对得上
（124 个值）。生产代码里不再有任何「写演示数据」的能力。
